# Stage 02: PRD

## Задача

Синтезировать bootstrap + референсы пользователя в Product Requirements Document для курса. Результат — `02-prd.md`.

## Инструкции

### 0. Roadmap

Покажи Roadmap (формат из SKILL.md) с `🔄 02 PRD` как текущим этапом.

### 1. Загрузи контекст

Прочитай:
- `courses/{slug}/01-bootstrap.md`
- Все файлы из `courses/{slug}/references/` (через Glob, Read)
- `courses/{slug}/references/links.md` (если есть — WebFetch каждую ссылку)

**Приоритет источников:** Референсы пользователя — ЕДИНСТВЕННЫЙ источник для формирования scope, топиков, модулей, learning outcomes и любых фактических данных. Ничего не выдумывай сверх того, что есть в bootstrap и референсах. Если для какой-то секции PRD данных в референсах не хватает — явно укажи это как пробел в тексте PRD и спроси пользователя, откуда взять недостающую информацию, вместо того чтобы додумывать.

### 2. Прочитай шаблон

### 3. Генерация PRD

**Задачи генерации:**

- [ ] Паспорт курса
- [ ] Learning Outcomes (Bloom's Taxonomy)
- [ ] Целевая аудитория
- [ ] Scope (включено / исключено)
- [ ] Топики и модули
- [ ] Практика
- [ ] Безопасность данных (если AI-курс)
- [ ] Инструменты
- [ ] Метрики успеха
- [ ] Риски

Заполни все секции шаблона:

**Паспорт курса** — из bootstrap + уточнения из референсов

**Learning Outcomes** — переработай из bootstrap, используя:
- Bloom's Taxonomy (конкретные глаголы: создать, применить, анализировать)
- Данные из референсов (что реально нужно ЦА, судя по загруженным материалам)

**Целевая аудитория** — обогати bootstrap-описание данными из референсов

**Scope** — определи что включено и что **сознательно исключено** (и почему)

**Топики и модули** — высокоуровневая таблица модулей с примерным временем. Проверь:
- Модули строятся **последовательно** — каждый опирается на результат предыдущего (нарастающая сложность)
- **Сквозной проект** пронизывает все модули — артефакт модуля N является входом для модуля N+1
- Максимум **1-2 основных инструмента** — глубина вместо ширины. Если референсы упоминают больше, сузь скоуп

**Практика** — каждый модуль должен содержать задание **"сделай это сейчас со своими данными"**, а не только демо-сценарии с вымышленными персонажами

**Безопасность** — если курс про AI-инструменты, включи правила работы с данными: что можно загружать, что нельзя, как анонимизировать. Не отдельный модуль — встроено в каждый модуль по контексту

**Инструменты** — выведи из референсов (bootstrap их больше не собирает). Ограничь до 1-2 основных

**Метрики успеха** — предложи реалистичные targets

**Риски** — на основе референсов и контекста курса

### 4. Проверка на соответствие принципам курса

Убедись что PRD соответствует базовым принципам качества:
- **Engagement** — есть элементы вовлечения (практика, быстрые wins)
- **Должен быть результат** — финальный артефакт чёткий и достижимый
- **Модульные навыки** — компактный курс с фокусом на конкретный навык
- **Экспертность** — контент основан на референсах, не поверхностный

### 6. Human Gate 1: PRD Review

Установи state:
```json
{
  "stages": {
    "02-prd": {
      "status": "review_pending"
    }
  },
  "current_stage": "02-prd"
}
```

Покажи пользователю ключевые секции PRD:
- Learning Outcomes
- Scope (включено / не включено)
- Таблицу модулей

Покажи Roadmap с `⏳ 02 PRD` (review_pending).

Используй **AskUserQuestion**:
- question: "PRD готов к ревью. Ваше решение?"
- options: `["Утвердить", "Правки", "Отклонить"]`

Если пользователь выбрал "Правки", используй **AskUserQuestion** (freeform, без options):
- question: "Опишите, что нужно изменить в PRD"

При утверждении:
```json
{
  "stages": {
    "02-prd": { "status": "approved", "completed_at": "..." }
  },
  "current_stage": "03-structure"
}
```

При правках — перезапусти генерацию с учётом фидбека. Сохрани фидбек в state:
```json
{
  "stages": {
    "02-prd": { "status": "revision", "feedback": "..." }
  }
}
```
